# SSTP Manager

Установщик SSTP-сервера с русскоязычной админ-панелью, локальными учётными записями и управляемым выходным каскадом. Публичный комплект содержит исходный код и шаблоны. Пользователи, пароли, SSH-ключи, сертификаты, адреса развёрнутых серверов и сохранённый exit в него не входят.

## Установка

Нужен чистый VPS с Ubuntu 22.04/24.04 либо Debian 12/13 (x86_64 или aarch64), root-доступом, systemd и обычным Linux-ядром с PPP, TUN, WireGuard, nftables и network namespaces. Контейнер без сетевых прав и соответствующей поддержки ядра не подходит. На сервере должны работать IPv4 и доступ к репозиториям пакетов. Эти версии допускаются проверкой установщика; это не утверждение, что каждая комбинация уже прошла полную установку и VPN-тест.

Создайте DNS A-запись домена на публичный IPv4 нового VPS. Если у домена есть AAAA-запись, она должна вести на этот же сервер с рабочим IPv6; неверную AAAA-запись нужно убрать. Для автоматического сертификата и дальнейшего продления извне должен быть доступен **TCP 80**. Также откройте выбранные порты SSTP и панели в firewall провайдера. Изменение локальных правил не открывает firewall в панели VPS-провайдера.

Войдите в терминал чистого сервера как `root` и вставьте одну команду установки из раздела «Команда из GitHub» ниже. Она сама скачает полный установщик во временный файл и запустит его. Загружать файлы на сервер вручную не требуется. Если вы используете обычную учётную запись с правами sudo, добавьте `sudo` в начало этой строки.

Установщик попросит:

1. Домен — например, `vpn.example.com`, без `https://` и номера порта.
2. TCP-порт SSTP.
3. TCP-порт админ-панели.
4. Пароль администратора панели — придумайте его сами и повторите для подтверждения.

Пароль спрашивается после установки базовых зависимостей и проверки ядра, перед настройкой VPN-сервера и приложения. При наборе он не отображается. Допустимы 12–128 символов, в том числе кириллица и пробелы внутри; пробелы по краям и управляющие символы не принимаются. Этот пароль предназначен для входа в админ-панель. Для каждого VPN-пользователя пароль задаётся отдельно при создании записи.

`install.sh` содержит всё приложение и вспомогательные скрипты. Интернет требуется для установки системных пакетов, загрузки исходников Accel-PPP и выпуска сертификата. Порты SSTP и панели должны различаться и не занимать порт HTTP-проверки сертификата или SSH. Остальные параметры и новые служебные ключи создаются автоматически. В конце установки будут показаны ссылка на панель, данные подключения и выбранный вами пароль администратора. Итоговый вывод содержит секрет: сохраните его приватно и не публикуйте скриншот терминала. Готовых VPN-пользователей нет: создайте первую запись в панели.

Панель открывается по **HTTPS** с выбранным портом. SSTP-порт предназначен для VPN-клиента, а не для просмотра панели в браузере.

## Команда из GitHub

Скопируйте строку целиком и вставьте в Termius на чистом VPS под `root`:

```bash
bash -c 'set -e; [[ $EUID -eq 0 ]] || { echo "Run as root" >&2; exit 1; }; : </dev/tty; command -v curl >/dev/null || { apt-get update; DEBIAN_FRONTEND=noninteractive apt-get install -y ca-certificates curl; }; d=$(mktemp -d /tmp/sstp-download.XXXXXXXX); cleanup() { rm -rf -- "$d"; }; trap cleanup EXIT; curl -fLsS --proto "=https" --proto-redir "=https" --connect-timeout 15 --max-time 120 -o "$d/install.sh" "$1"; test -s "$d/install.sh"; bash "$d/install.sh";' sstp-download https://raw.githubusercontent.com/yuliamurmur530/sstp-manager/main/install.sh
```

Команда сама устанавливает `curl`, если его нет, полностью скачивает установщик во временную приватную папку и только после успешной загрузки запускает его. После завершения временная папка удаляется. Домен, порты и пароль не нужно вписывать в команду: установщик спросит их в терминале. Обычный `curl | bash` для этого самораспаковывающегося установщика не подходит.

В [репозитории SSTP Manager](https://github.com/yuliamurmur530/sstp-manager) находятся готовый `install.sh`, этот README, архив `sstp-installer-source.zip` со всеми читаемыми исходниками и тестами, а также `sstp-installer-SHA256SUMS.txt`. Сам установщик тоже содержит исходники приложения: `bash install.sh --extract NEW_DIRECTORY` распакует их без установки.

Для разработчиков: скачайте и распакуйте исходный ZIP, затем перейдите в каталог `sstp-installer/`. Другую команду запуска можно сформировать через `python3 tools/make_install_command.py --compact --url URL_НА_INSTALL.SH`. Без `--compact` выводится расширенный загрузчик с поддержкой `curl` и `wget`. Для воспроизводимости используйте URL конкретного commit или выпуска. Необязательный `--sha256` задаёт доверенную контрольную сумму всего скачиваемого файла; проверка встроенного архива сама по себе не удостоверяет источник загрузки.

Если `install.sh` уже лежит на сервере, его также можно запустить командой `sudo bash install.sh`. Это дополнительный способ, перенос файла вручную для установки из GitHub не требуется.

## Подключение пользователей

В панели добавьте имя, пароль и постоянный адрес; кнопка «Свободный IP» подставляет свободный адрес. В SSTP-клиенте укажите домен установки, выбранный SSTP-порт, имя вида `user@VPN` и пароль этой записи. Проверку сертификата оставьте включённой. Порт обычно задаётся в настройках клиента отдельно от имени сервера.

Одна запись соответствует одному активному подключению. Новый вход той же учётной записью заменяет предыдущую сессию.

Начальная VPN-сеть — `10.77.0.0/24`, шлюз — `10.77.0.1`, пользовательский пул — `10.77.0.10–10.77.0.249`. Адрес `.250` отведён для административного доступа, `.253` — для проверки выхода, `.254` — служебный адрес первичной настройки. Эти адреса обычным пользователям не выдаются.

## Возможности

- Создание, удаление и отключение пользователей, постоянные IPv4, предложение свободного IP, online-статус и текущий адрес.
- Автообновляемая таблица, месячные и пользовательские счётчики трафика, отдельный сброс отображаемого отсчёта без уничтожения месячного учёта.
- Пул адресов, включение/выключение NAT, разрешённые частные сети, маршруты к сетям за клиентским роутером.
- Проброс TCP/UDP-портов на выбранного пользователя, подбор свободного порта, диагностика и доступ к пробросам из VPN.
- Изоляция клиентов, правила маршрутизации и восстановление правил службами systemd.
- Просмотр журналов, резервная копия конфигурации через панель.
- Автоматический сертификат домена и продление с применением сертификата к службам.
- Прямой выход в интернет либо отдельный выход через каскад; кнопки включения/выключения.
- Подготовка exit-сервера через SSH с указанным портом: вход root по паролю или приватному ключу, автоматическое разрешение служебного публичного ключа, установка компонентов, выбор свободного UDP-порта, настройка туннеля, проверка handshake и фактического внешнего IP, переключение или возврат рабочего режима при ошибке.
- Прогресс подготовки в панели: шесть этапов, текущее действие, история с временными отметками, прошедшее время и этап ошибки. Проценты обозначают этапы, а не измеренную долю времени установки.

Для SSTP используется Accel-PPP и локальное хранение учётных записей. RADIUS и SoftEther не устанавливаются. WireGuard используется как транспорт между входным SSTP-сервером и дополнительным exit; клиентские устройства подключаются по SSTP.

## Новый выход каскада

После установки каскад выключен и сохранённого exit-IP нет. Нужен принадлежащий вам Ubuntu/Debian VPS с доступом **root** по SSH. Заранее настраивать на нём туннель, подбирать UDP-порт или добавлять служебный SSH-ключ вручную не требуется.

В блоке «Выход SSTP-каскада» заполните:

1. Публичный IPv4 нового exit.
2. Его SSH-порт — `22` по умолчанию; если вы входите на другом порту, укажите этот порт.
3. Способ входа: **SSH-пароль** (выбран по умолчанию) или **приватный SSH-ключ**.
4. Пароль root либо файл/текст полного приватного ключа в формате OpenSSH или PEM. Для зашифрованного ключа укажите его пароль; для незашифрованного оставьте поле пустым. Используйте что-то одно: файл ключа или вставленный текст. Публичный `.pub` и формат PuTTY `.ppk` не подходят; лимит приватного ключа — 32 КБ.

Нажмите «Подготовить и переключить». Панель покажет этапы подключения, подготовки сервера, проверки туннеля и выхода в интернет. SSH-порт не связан с UDP-портом туннеля: свободный UDP-порт подбирается автоматически. Если провайдер фильтрует UDP, разрешите выбранный порт в его панели.

При первом входе установщик добавляет на exit только **служебный публичный ключ этой установки**, сохраняя существующие строки `authorized_keys`. Затем проверяет повторный вход по служебному ключу и использует его для дальнейшего управления; SSH-порт сохраняется отдельно для каждого exit. Закрытый служебный ключ не копируется на exit. Отдельного варианта «сохранённый ключ» в форме нет.

Введённый пароль, загруженный приватный ключ и его пароль не записываются в настройки, журнал или резервную копию панели. Они передаются службе через стандартный ввод и временно хранятся в закрытом каталоге `/run`, после проверки доступа удаляются; очистка предусмотрена и при остановке/ошибке задачи. После неопределённого ответа systemd данные не удаляются, пока задача может работать; осиротевшие данные старше 20 минут очищаются при проверке статуса только после подтверждения, что задача не выполняется. Первый SSH-вход запоминает ключ самого сервера; при его последующей смене подключение отклоняется.

Пароль или ключ должен действительно разрешать вход root на новом VPS. Наличие одного IP не даёт доступа к произвольному серверу. Резервную копию вашей установки храните приватно: она содержит служебный ключ для управления уже подготовленными exit.

«Выключить каскад» возвращает прямой выход через входной сервер. «Включить каскад» использует уже настроенный exit. Старый управляемый туннель удаляется только после успешной замены; чужие туннели не должны изменяться.

## Сертификат и резервные копии

Для выпуска и продления сертификата сохраняйте домен направленным на этот сервер, а TCP 80 — доступным. Применение обновлённого сертификата к SSTP может потребовать перезапуска службы и краткого переподключения клиентов; проверяйте журнал продления.

Резервная копия, скачанная из работающей панели, содержит **секреты и данные пользователей вашей установки**. Храните её приватно. В GitHub загружается только этот исходный комплект, а не архив панели, каталог `/etc`, содержимое установленного приложения или вывод финальных учётных данных.

## Проверка перед публикацией

```bash
python3 tools/check_release.py --self-test --source-only
python3 tools/build_release.py
python3 tools/check_release.py --self-test
```

Сборщик создаёт готовый `install.sh`, исходный архив `sstp-installer-source.zip` и файл контрольных сумм `sstp-installer-SHA256SUMS.txt` рядом с каталогом проекта. При изменении `installer.sh`, `payload/`, `requirements.txt` или файлов в `scripts/` пересоберите файл установки перед публикацией.

Проверка принимает только ожидаемые исходные файлы, ищет явные ключи/секреты, персональные пути, неразрешённые домены и публичные IPv4, проверяет Python-синтаксис. В готовом `install.sh` проверяется также встроенный архив и его совпадение с текущими исходниками. Дополнительные приватные названия можно передать как повторяющийся аргумент `--forbid-token`; сами значения в отчёте не печатаются. `.gitignore` дополнительно исключает типичные секреты, состояние и архивы.

В исходном архиве есть workflow `.github/workflows/validate.yml` для GitHub Actions: если разместить исходное дерево в корне репозитория, он запускает эти проверки, `bash -n` и изолированные тесты логики панели, учётных записей, маршрутов и каскада с подменой системных команд. Архив ZIP сам по себе не запускает Actions. Эти тесты не доказывают работу VPN: перед эксплуатацией отдельно проверьте установку на чистой VM, TLS, вход клиента, интернет, замену сессии, проброс портов, reboot, продление сертификата и каскад на подготовленном exit. Проверку в мобильной сети нужно выполнять с реального клиентского устройства.

Дополнительная проверка настоящего синтаксиса nftables на Linux: `sudo bash tools/test_nft_namespace.sh`. Она требует уже установленных `iproute2`, `nftables`, `util-linux` и Python; выполняется в отдельном сетевом namespace без выхода в сеть. Правила рабочего сервера не меняет и пакеты не устанавливает.

Автоматические тесты охватывают шаблоны установки, разбор JavaScript отрендеренной панели, ввод пароля, оба варианта команды запуска из GitHub и неблокирующий запуск каскада с сохранением ошибок фонового процесса. Проверки SSH-учётных данных используют подменённые системные вызовы: они не подключаются к exit и не запускают настоящий каскад. Полная установка этой версии на чистую VM, выпуск сертификата, реальный SSTP-вход и подготовка exit ещё не выполнялись.

## Лицензии

Перед публичным распространением выберите лицензию для кода этого проекта, права на который у вас есть. Этот комплект не назначает лицензию от имени владельцев исходного приложения. Accel-PPP, nginx, WireGuard, Python-пакеты и другие устанавливаемые зависимости сохраняют собственные лицензии; их уведомления и требования нужно учитывать отдельно. Сторонние бинарные сборки и приватные серверные архивы в репозиторий не включены.

Исходные проекты и документация: [Accel-PPP](https://github.com/accel-ppp/accel-ppp), [Certbot](https://github.com/certbot/certbot), [Let's Encrypt](https://letsencrypt.org/docs/), [nginx](https://nginx.org/en/), [WireGuard](https://www.wireguard.com/), [Flask](https://github.com/pallets/flask), [Gunicorn](https://github.com/benoitc/gunicorn). Зависимости Python перечислены в `requirements.txt`; системные пакеты — в `installer.sh`.
